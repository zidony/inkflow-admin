# InkFlow Admin Integration Guide

This guide explains how to integrate the built `dist/` output into a backend project or static hosting target.

## Build Output

Run:

```bash
npm run build
```

The generated `dist/` directory contains static HTML, CSS, JavaScript, fonts, and image assets. The release ZIP generated by `npm run release` includes the same built files plus `README.md`, `README.en.md`, and this integration guide.

## Static Deployment

### Nginx

Copy `dist/` to the server directory used by Nginx, for example `/var/www/inkflow-admin`.

```nginx
server {
  listen 80;
  server_name admin.example.com;
  root /var/www/inkflow-admin;
  index index.html;

  location / {
    try_files $uri $uri/ /index.html;
  }
}
```

### Apache

Copy `dist/` to the Apache document root or a virtual host directory.

```apache
<VirtualHost *:80>
  ServerName admin.example.com
  DocumentRoot "/var/www/inkflow-admin"

  <Directory "/var/www/inkflow-admin">
    Require all granted
    AllowOverride All
  </Directory>
</VirtualHost>
```

### GitHub Pages

Build the project and deploy `dist/` as the Pages artifact. This repository already includes a Pages workflow in `.github/workflows/deploy.yml`.

### Backend Template Directory

For frameworks such as Laravel, Django, Rails, Express, Spring Boot, or ASP.NET:

- Copy HTML files from `dist/` into the framework's template/view directory.
- Copy `dist/assets/` into the public/static asset directory.
- Keep asset paths stable, or update links to match the framework's asset helper.
- Replace mock data blocks with server-rendered values or API-driven rendering.
- Preserve `data-action` attributes if you want to keep the built-in JavaScript behavior.

## Customization Points

### Theme Colors

Primary theme variables live in `src/assets/css/_variables.css`. Start with brand, state, gray scale, radius, spacing, and shadow variables before changing component CSS. See `docs/theme-customization.md` for the recommended override map.

After changing source CSS, rebuild:

```bash
npm run build
```

### Logo

Update `src/partials/sidebar.html`:

- `.sidebar-logo-icon` controls the icon area.
- `.sidebar-logo-title` controls the main brand label.
- `.sidebar-logo-sub` controls the secondary label.

### Menu

Update `src/partials/sidebar.html` for navigation groups and page links. For collapsible groups, keep `data-toggle="submenu"`, `data-target`, `aria-controls`, and `aria-expanded` aligned with the submenu `id`.

### Permission Entry Points

Use backend authorization to decide whether to render menu entries, action buttons, or form controls. Client-side hiding is useful for clarity, but it should not be treated as the permission boundary.

## Offline and Intranet Delivery

InkFlow Admin is designed to run from local build assets. Before shipping a release package, run:

```bash
npm run build
npm run release:check
```

The release check verifies version consistency, required release files, blocked package contents, and external resource references in source/build files.

## Release Package Rules

Release packages should not contain:

- Source directories such as `src/`
- Dependency directories such as `node_modules/`
- Temporary directories such as `temp/`
- Python helper scripts
- Project duplicate `.woff` font formats when `.woff2` is available
- External runtime resource references inside built files
